================================================================================
                    JAVA EXCEPTION HANDLING - COMPLETE GUIDE
================================================================================

1. WHAT IS AN EXCEPTION?
   - An unwanted event that disrupts the normal flow of a program
   - Occurs during runtime (not compile-time)
   - Examples: Division by zero, null pointer access, file not found

2. EXCEPTION HIERARCHY
   
   Object
     └── Throwable
           ├── Error (Unchecked - JVM errors, cannot be handled)
           │     └── OutOfMemoryError, StackOverflowError
           │
           └── Exception (Can be handled)
                 ├── Checked Exceptions (Compile-time checked)
                 │     └── IOException, SQLException, ClassNotFoundException
                 │
                 └── RuntimeException (Unchecked)
                       └── NullPointerException, ArithmeticException,
                           ArrayIndexOutOfBoundsException

3. CHECKED vs UNCHECKED EXCEPTIONS

   CHECKED EXCEPTIONS:
   - Must be handled or declared using throws
   - Checked at compile-time
   - Examples: IOException, SQLException, FileNotFoundException
   
   UNCHECKED EXCEPTIONS:
   - Not checked at compile-time
   - Subclasses of RuntimeException
   - Examples: NullPointerException, ArithmeticException

4. EXCEPTION HANDLING KEYWORDS

   a) try:
      - Block of code that might throw an exception
      - Must be followed by catch or finally
      
   b) catch:
      - Handles the exception thrown by try block
      - Can have multiple catch blocks for different exceptions
      
   c) finally:
      - Always executes regardless of exception
      - Used for cleanup (closing files, connections)
      - Optional but recommended
      
   d) throw:
      - Explicitly throws an exception
      - Used inside method body
      - Syntax: throw new ExceptionType("message");
      
   e) throws:
      - Declares exceptions a method might throw
      - Used in method signature
      - Syntax: void method() throws IOException { }

5. TRY-CATCH-FINALLY FLOW

   try {
       // Code that may throw exception
   } catch (ExceptionType1 e) {
       // Handle ExceptionType1
   } catch (ExceptionType2 e) {
       // Handle ExceptionType2
   } finally {
       // Always executes (cleanup code)
   }

6. BEST PRACTICES

   ✓ Catch specific exceptions first, then general ones
   ✓ Don't catch Exception or Throwable unless necessary
   ✓ Always log exceptions for debugging
   ✓ Use finally for resource cleanup or try-with-resources
   ✓ Create custom exceptions for business logic errors
   ✓ Don't use exceptions for control flow
   ✓ Include meaningful error messages
   ✗ Never leave catch block empty
   ✗ Don't catch exceptions you can't handle

7. TRY-WITH-RESOURCES (Java 7+)

   - Automatically closes resources that implement AutoCloseable
   - No need for explicit finally block
   
   Syntax:
   try (ResourceType resource = new ResourceType()) {
       // Use resource
   } catch (Exception e) {
       // Handle exception
   }

8. CUSTOM EXCEPTIONS

   - Extend Exception (checked) or RuntimeException (unchecked)
   - Provide constructors for message and cause
   - Use for domain-specific errors
   
   Example:
   class CustomException extends Exception {
       public CustomException(String message) {
           super(message);
       }
   }

9. COMMON EXCEPTIONS

   NullPointerException        - Accessing null object
   ArithmeticException         - Math errors (divide by zero)
   ArrayIndexOutOfBoundsException - Invalid array index
   NumberFormatException       - Invalid string to number conversion
   ClassCastException          - Invalid type casting
   IOException                 - Input/output operations fail
   FileNotFoundException       - File doesn't exist
   SQLException                - Database errors

10. EXCEPTION METHODS

    getMessage()     - Returns exception message
    toString()       - Returns exception class name and message
    printStackTrace() - Prints stack trace to console
    getCause()       - Returns cause of exception
    getStackTrace()  - Returns array of stack trace elements

11. MULTIPLE CATCH BLOCKS ORDER

    CORRECT:
    try { }
    catch (FileNotFoundException e) { }  // Specific
    catch (IOException e) { }            // General
    
    WRONG:
    try { }
    catch (IOException e) { }            // General first
    catch (FileNotFoundException e) { }  // Unreachable code!

12. WHEN TO USE throw vs throws

    throw:
    - Inside method body
    - Actually throws the exception
    - throw new Exception();
    
    throws:
    - In method signature
    - Declares potential exceptions
    - void method() throws Exception { }

Syntax Summary:

1. Basic:           try { } catch (Exception e) { }
2. Multiple:        try { } catch (E1 e) { } catch (E2 e) { }
3. Finally:         try { } catch (E e) { } finally { }
4. Throw:           throw new Exception("message");
5. Throws:          void method() throws Exception { }
6. Custom:          class MyException extends Exception { }
7. Try-Resource:    try (Resource r = new Resource()) { }
8. Nested:          try { try { } catch { } } catch { }
